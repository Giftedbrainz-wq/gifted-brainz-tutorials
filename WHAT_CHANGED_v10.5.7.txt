GIFTED BRAINZ TUTORIAL — v10.5.7 (deploy fix)

Problem
-------
Login on the student and admin portals reported:
"The API is not responding on this site: the server returned a web page
instead of data. The serverless function was not published with this deploy."

The backend code was fine. The packaging was the problem: the site published
the repository root ("publish = ."), ran a pointless build command, and left
the Netlify UI free to publish a directory that did not carry the function —
so /api/* fell through to the single-page fallback and answered index.html.

Changes (no student content, CBT questions, materials or API logic touched)
--------------------------------------------------------------------------
1. All static files moved into public/ ; netlify.toml now publishes "public".
   Static site and backend now live in separate folders, so the publish
   directory can never include or omit the function by accident.
2. netlify.toml: build command emptied, functions = "netlify/functions",
   Node 20, esbuild bundler, /api/* redirect forced above the SPA fallback.
3. build.mjs and the "build" npm script removed (they only printed a message
   and could fail a deploy). package.json now declares "type": "module".
4. New dependency-free probe function netlify/functions/ping.mjs -> /api/ping.
   It proves whether functions were published at all.
5. public/_redirects rewritten: /api/ping and /api/* forced to the functions
   ahead of the /* -> /index.html fallback.
6. diagnostics.html now runs the /api/ping probe first and states plainly
   which layer is broken: functions not deployed, API function crashing, or
   storage unavailable.
7. GITHUB_DEPLOYMENT_FIRST.txt and DEPLOYMENT.md rewritten for the new layout
   and exact Netlify settings. The stale GITHUB_NETLIFY_DEPLOY.txt was removed.
